About the workflow

Lin Ye Studio tours a photographic exhibition across venues where the network is unreliable or deliberately switched off. The selection desk — which prints, which photo opens a series, what order a room reads in — keeps moving during install week. This site is built around that constraint.

One catalog, every page

Home, Works, Series, About and Contact all read the same catalog object. Filter the works down to a series, follow a link to another page and come back: the range is persisted, and the lightbox only ever walks the photographs in the current result set.

Merge by photo baseline

When the link returns, the venue copy is merged against the touring draft that originally left the station. Edits made on only one side fast-forward automatically. When both sides edited the same photograph differently, neither overwrites the other: both values stay as candidates until a human picks one. If the fetch or the structural merge fails, nothing is committed — the desk returns to the original draft and retries from there.

Recompute together

Only after a merge is confirmed do the derived views update in one pass: series covers (the first selected photograph in canonical order), the lightbox sequence, and every filtered result set.

Fully local assets

Photographs, the three typefaces (Playfair Display and Inter) and all scripts are served from the site itself. A service worker precaches the whole portfolio, so the venue laptop works unplugged, and the contact form queues messages until the station link is back.
